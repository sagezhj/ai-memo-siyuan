# AI Memo → SiYuan（Edge / Chrome MV3 扩展）

自动、静默地把 **千问 / DeepSeek / 元宝** 网页里的 AI 对话增量抓下来，先落本地，再**按块增量写入思源笔记**。
思路来自 Chat Memo（一泽Eze）：不做手动剪藏，页面里聊完就存；差异在于终点不是插件自己的库，而是你自己的思源文档树。

**零构建**：全部是经典脚本（无打包、无 ESM、无依赖），下载下来直接在 Edge 里「加载已解压的扩展程序」就能跑。

---

## 1. 安装

1. 关闭正在运行的思源？不用关，思源桌面版默认在本机 `6806` 端口跑内核 HTTP 服务。
2. Edge 打开 `edge://extensions`，左下角打开「**开发人员模式**」。
3. 点「**加载已解压的扩展程序**」，选择本目录（含 `manifest.json` 的那层）：
   `ai-memo-siyuan/`
4. 工具栏出现图标后点一下，会打开设置页。

> 同包在 Chrome 上也能装：`chrome://extensions` → 开发者模式 → 加载已解压。

## 2. 思源侧要准备的两件事

| 项 | 在哪找 | 说明 |
| --- | --- | --- |
| API 地址 | 思源 `设置` → 搜「网络」/「端口」（不同版本措辞略有差异） | 桌面版本机默认 `http://127.0.0.1:6806`；改过端口就填改后的 |
| 认证码 | 同一区域的「访问授权身份验证 / API 密钥」 | 一串随机字符，复制备用 |

思源需要处于运行状态；内核没起来时插件不会丢数据，会进重试队列（见 §5）。

### 思源不在本机（局域网 / 另一台机器 / Docker 映射）

填 `http://192.168.x.x:8026` 这类**非回环地址**时，点「测试连接」会弹一次浏览器授权窗（问你是否允许扩展访问 `http://192.168.x.x/*`），**必须点「允许」**。

原因是浏览器的 Private Network Access 规则：扩展属于安全上下文，向私网地址发请求要做预检，而思源内核对预检回的是 `Access-Control-Allow-Private-Network: false`，请求会被直接掐掉。拿到 host 权限后这条限制对扩展不生效，所以能正常读写。

两点注意：授权粒度是**主机**，不含端口（匹配模式不允许带端口），所以换端口不用重新授权；如果弹窗没出现或被拒了，去 `edge://extensions` → 本扩展 → 详情 → 「网站访问权限」手动加上该地址，再回来点测试。

> 商店发布版的 `manifest.json` **不预置任何局域网主机**：首次填非回环地址时，点「测试连接」会当场发起授权弹窗（不再排在异步保存之后），点「允许」即可；失败时按钮旁会显示浏览器返回的真实原因。如果你是自己打包分发，也可以把自己的思源主机写进 `host_permissions`（形如 `"http://192.168.x.x/*"`，匹配模式不带端口），安装后即免弹窗。

## 3. 首次配置（设置页四步）

1. **思源连接**：填 API 地址 + 认证码 → 点「测试连接并加载笔记本」→ 在笔记本下拉里选目标笔记本 → 「保存连接设置」。
   可选项：根路径（默认 `/AI对话`）、子目录模板（默认 `{yyyy-MM}/{platform}`）、标题前缀、文档头是否写入原链接 / 同步时间 / 模型名。
2. **抓取**：总开关、是否自动同步到思源、页面悬浮入口（气泡 + 会话面板）、会话面板样式（悬浮窗 / 侧边栏）、单次对话最大消息数（默认 500，超出则截断，警告会留在本地记录里，设置页列表可见）、四个平台各自的开关。
3. **页面诊断**：在已登录的对话页上点「扫描当前页面」，插件会把该页面的重复结构候选、正文锚点候选、当前抽取结果条数打印出来——选择器失效时按这里给出的值去第 4 步覆盖。
4. **选择器覆盖**：一段 JSON，只追加、不替换，改完立即生效，无需重装或改代码。

```json
{
  "deepseek": {
    "contentAnchorSelectors": [".ds-markdown"],
    "rowSelectors": ["[data-message-id]"]
  }
}
```

## 4. 日常使用

打开任一受支持平台的对话页，正常聊天。页面右下角有个小胶囊（气泡）：

| 显示 | 含义 |
| --- | --- |
| `AI Memo：读取页面` | 刚进页面，还没抓到内容 |
| `AI Memo：同步中` | 检测到新内容，正在写思源（图标转圈） |
| `AI Memo：已写入思源 · N 条` | 与思源一致，N 是当前对话消息数 |
| `AI Memo：排队中（待同步 N）` | 思源没连上，已进重试队列，N 是全部待处理对话数 |
| `AI Memo：同步失败` | 认证码/地址/笔记本问题，鼠标悬停看详情 |
| `AI Memo：本对话已暂停` | Alt/Ctrl+点气泡，或在面板里点「暂停」 |
| `AI Memo：此页未匹配到适配器` | 域名在注入范围内但没命中任何描述符 |

工具栏图标上的红色数字 = 待同步条数。文档写好后，在思源里刷新一下文档树即可看到。

### 会话面板（Chat Memo 式列表）

**点一下气泡**展开会话面板，再点一下（或按 Esc / 右上角 ×）收起。面板里是所有已捕获对话的实时列表：

- 每行显示：平台标签、标题、消息条数、同步状态（已同步 / 待同步·重试N / 等页面回开 / 失败 / 已暂停）、最后同步的相对时间；**当前页的对话置顶并高亮「当前页」**。
- 顶部汇总「N 个对话 · 已同步 X · 待同步 Y」，搜索框可按标题 / 平台 / 文档路径过滤。
- 点行主体 → 新标签页打开原对话；行右侧按钮：**思源**（经 `siyuan://blocks/<docId>` 协议跳到对应文档，需本机装有思源桌面端；浏览器版思源用户可按行悬停提示里的文档路径手动定位）、**暂停/恢复**、**重试**（仅待同步或失败的行）。
- 底部「立即同步本页」强制重扫当前对话，「设置」打开扩展设置页。
- 右上角可在**悬浮窗**（默认，右下角，拖标题栏可移动并记住位置）与**侧边栏**（贴右全高，展开时气泡自动隐藏）之间切换，选择会保存。
- 面板打开期间每 5 秒兜底刷新，每次同步状态回推也会即时刷新；列表最多渲染 100 行，更多请用搜索。

## 5. 它是怎么「增量」的

一篇对话 = 一个思源文档。首次创建时只写**文档头**，之后**每条消息单独 `appendBlock`**，因此每条消息的块 ID 都记在本地映射里。

再次抓取时做角色+内容指纹比对，产出最小操作集：

| 变化 | 动作 |
| --- | --- |
| 尾部新增（流式输出的主路径） | 只 `appendBlock` 新增的那几条 |
| 中间某条被改（重新生成、编辑重发） | 定位该条的块，`updateBlock`；多块时 `deleteBlock` + 以上一条的尾块为锚 `insertBlock`，**顺序不会乱** |
| 尾部删除 | 删掉对应块 |
| 中段插入 / 结构大改 | 整篇正文重建（文档头保留） |
| 内容没变 | 零请求 |

每一步成功都立刻落本地映射，中途失败重试时从断点继续，不会重复追加。失败按 `10s → 30s → 1min → 5min → 15min → 30min → 1h` 退避，后台每 2 分钟巡检一次队列；没有正文快照的旧条目会一直等到你重新打开那个对话页。

抓取时机不猜「流结束没」，而是**静默窗口**：页面 1.5 秒无变化才提交；检测到疑似「正在生成」指示器就一直延长，最长 12 秒兜底。切会话走 URL 轮询（800ms），关页面时 `pagehide` 补一次提交。

## 6. 落位与命名

```
/AI对话/2026-11/DeepSeek/我们聊的那件事
/AI对话/2026-11/千问/RAG 方案评估
```

文档头：

```markdown
# 我们聊的那件事

- 平台：DeepSeek
- 同步时间：2026-11-09 19:20:31
- 原对话：https://chat.deepseek.com/a/chat/s/xxxxxxxx
- 会话：xxxxxxxx
```

正文每条消息是四级标题（`#### 3. 助手 · 19:20`）+ 内容，代码块保留围栏与语言，表格、嵌套列表、引用、行内格式都走 DOM→Markdown 序列化；页面上的「复制 / 重新生成 / 点赞」等按钮节点会被排除。

> 文档头只在**首次创建**该文档时写入；后续增量只更新正文与文档标题。想改元信息开关，对已有对话可在「本地记录」删除记录后重扫。

## 8. 本机验证（没有 Node 也能跑）

用 Edge/Chrome 直接打开这两个文件（`file://` 即可）：

- `src/pages/selftest.html` —— 加载真实模块跑断言，覆盖哈希、命名清洗、**增量 diff 语义**、DOM→Markdown、思源响应解析、抽取引擎（含 DeepSeek 结构样例与「行选择器全落空时用正文锚点反推」的兜底路径）、会话面板纯逻辑（相对时间、状态推导、搜索与置顶）。当前 **56/56 通过**。
- `src/pages/syntaxcheck.html` —— 把 20 个源文件逐个交给浏览器编译，区分「语法错误」与「运行时提示」。当前 **20/20 通过**。

改完代码再点开这两个页面看一眼，是本项目的主要回归手段。

## 9. 已验证 / 未验证

**已在本机真实执行并验证**：纯逻辑层（指纹、清洗、文档定位、diff 全部语义分支、退避曲线、host 权限模式去端口）、DOM→Markdown 序列化、思源响应解析（`doOperations` 取块 ID、`data` 三种形态）、抽取引擎在构造 DOM 样例上的端到端结果、会话面板在真实 DOM 上的冒烟测试（挂载、列表渲染、当前会话置顶、悬浮/侧边栏切换与持久化、搜索、Esc 收起）、全部源文件可编译。

**已对着真实内核验证**（思源 3.8.9）：代码里用到的 11 个接口路径全部存在——`/api/system/version` 免鉴权返回 `{"code":0,"data":"3.8.9"}`，`lsNotebooks`、`createDocWithMd`、`appendBlock`、`insertBlock`、`updateBlock`、`deleteBlock`、`renameDoc`、`removeDoc`、`setBlockAttrs`、`getBlockKramdown` 均返回 `401 Auth failed [session]`（路由在，只是要认证码）；带 `chrome-extension://` Origin 不会被内核的来源白名单拒。顺带确认 `/api/version`、`/api/sql/query`、`/api/block/batchOperations` 在该版本**不存在**，插件没有依赖它们。

**仍需你在自己环境里确认**：

1. **三个平台的真实 DOM**。这些页面要登录，我这边进不去，所以 `adapters/*.js` 里的选择器是按常见实现写的**候选猜测**。第一次用的正确姿势：打开对话页 → 设置页「页面诊断」→ 看「抽取 N 条」是不是实际条数、角色对不对 → 不对就把诊断给出的候选选择器填进「选择器覆盖」保存。**不需要改代码**。
2. **带认证码之后的写操作响应体**。上面的探测止步于鉴权（没有认证码），所以 `doOperations` 里块 ID 的具体层级、`createDocWithMd` 返回的文档 ID 形态仍是按官方文档实现的。第一次同步成功后到思源里看文档是否完整，第二次改动看是否只动了对应那一条，即可确认；若报 `siyuan-<code>`，把 code 和设置页日志发我，改 `siyuan.js` 一处即可。
3. **扩展在 Edge 里的实际加载**。本机没有 Edge 加载已解压扩展的自动化入口，manifest 字段与注入顺序做了静态核对（脚本依赖顺序、`importScripts` 与清单一致、权限覆盖所有目标域与回环地址、`optional_host_permissions` 覆盖动态授权所需的 http/https 主机），但「装上去能跑」这一步只能由你点一下确认。

## 10. 数据与隐私边界

- 对话正文**只**经过 `chrome.storage.local` 与本机思源内核，不上传任何第三方；认证码不参与 `storage.sync`。
- 本地记录映射里**只存角色与哈希**，不存正文；正文快照只在「未同步成功」期间留在重试队列里，同步成功即清除。
- 「删除记录」只删本地映射，**不会删思源里的文档**；想删文档请自己在思源里操作。
- 目标平台改版导致抽取失败时，最坏结果是「不写入」，不会写出半截内容覆盖你的文档。

## 11. 已知限制

- 只处理顶层框架；对话在 iframe 里的站点需要另配（`all_frames` 目前为 `false`）。
- 图片、文件附件只留占位说明（`[图片]`），不下载、不转存到思源资源目录。
- 多设备同一账号的思源同步由思源自己负责，插件只写本机内核。
- 一次会话超过 500 条会截断并在文档里标注（阈值可调）。
- 中段插入会触发整篇正文重建，块 ID 变化后原块上的批注/引用会失效——这是「顺序正确」换来的代价。

## 12. 常见报错速查

| 报错文字 | 含义 | 处理 |
| --- | --- | --- |
| `建文档失败：siyuan--1 document metadata is not ready` | 思源 3.8.x 的 `createDocWithMd` **不会自动创建父文档**：目标 h-path 的父目录链（如 `/AI对话/2026-11/元宝`）缺失时就报这句（`indexUnavailable`）。只建了笔记本、没建中间目录也会触发 | 插件现在会先用 `/api/query/sql` 查父链、自上而下补齐缺失的父目录，再建叶子文档，无需手动建目录。**重新加载扩展**后点「立即重试待同步」即可。若补齐后仍报同句，才是索引未就绪：在思源打开该笔记本等索引/重建索引完成 |
| `失败（bad-token）… Auth failed [session]` | 认证码不对或没填 | 复制思源「设置→API」的认证码整段粘贴，保存后重测 |
| `失败（blocked）…` | 浏览器拦了跨网段请求，缺该主机授权 | 重新加载扩展（清单已预置你的局域网主机）；或按 §2 手动/弹窗授权 |
| `失败（unreachable）…` | 内核没启动或地址/端口错 | 确认思源在跑、地址端口对；本机建议用 `127.0.0.1` |
| `失败（http-404）…` | 接口路径在该思源版本不存在 | 把版本号发我；插件已避开 3.8.9 不存在的接口 |
| 扩展管理页报 `Permission 'http://*/*' is unknown.` | MV3 里主机匹配模式不能放进 `optional_permissions`，要用 `optional_host_permissions` | 本仓库已修正为 `optional_host_permissions`；重新加载扩展后该报错消失，换新思源地址时的授权弹窗也才能真正生效 |

## 13. 加新平台

复制 `src/content/adapters/generic.js` 的写法，写一个只含选择器候选数组的描述符，末尾 `AIME.engine.register(AIME.adapters.xxx)`，然后在 `manifest.json` 的 `host_permissions` / `content_scripts.matches` / `src/shared/constants.js` 的 `PLATFORMS` + `DEFAULT_SETTINGS.platforms` 各加一项。算法不用动。
